# 设计裁决（代码里看不出动机）

记录代码本身看不出、改动前必须知道的取舍。条目按主题分组，新裁决追加到对应分组末尾；被推翻的条目就地改写。每条只写「结论 + 必要理由」；宿主侧依据引 [`host-api.md`](host-api.md)，UI 数值引 `src/client/card-styles.ts`。

## 解析与填充

- **配置解析优先级**：当前版本快照 → ≥ 最低支持的最高可解析快照（降级解析，多余键忽略、`efforts` 宽松保留）→ 内置默认。降级落盘的更高版本快照永不清理（再升级可无损回退）；当前快照非法**或残缺**按当前生效值规范化重写（残缺会被补默认判合法，须比对规范化结果而非只判非法）。
- **`allowUpdate` 含缺失补写，`autoFill` 关闭不拦**：语义是「以目录为准同步该字段」；新旧相同跳过，目录无档位不删已有配置。
- **`force` 是单次绕过**：三项临时为真、不落存储、不重拉目录（网络耗时不计入按钮反馈）；`fix` 返回值只计模型变更数（compat 不计入，保持 RPC 反馈契约）。
- **`fix` 读 `descriptor.user`（原始用户段）**：避免规范化形态与写入形态不一致反复触发重写；写回带 revision 围栏，冲突重读重算（限次）；写失败先告警再抛出（事件侧吞 rejection，RPC 转 `ok:false`）。
- **空壳字段判据只有 `stripEmptyFields` 一处**（`reasoningEfforts` / `input` / `compat` 空形态等同未声明）：五条写回路径（`fix` 填充、`reset`、`restore`、`fill` 两次写回、`probe-backup` 回退）统一过它，任何一处不另写判据。无空壳返回原引用，调用方以引用相等判「无需重建」。`fix` 缺失补写按清理后的值认；`reset` 的写回触发只看「带没带推理级别」。`compat.ts` 的路由级整段 `unset` 是另一作用域，不经此函数。
- **compat「开启即添加、关闭即移除」，与模型参数取向相反**（后者关闭只是不写、存量保留）——compat 是本插件接管的路由字段。两条规则共用 `openai-completions` 协议 gate 与同一写入路径，均默认开启（宿主对未标注端点按「支持」乐观处理，本插件翻成保守）；只写路由级（模型级优先，会与用户取值打架），非目标协议仅残留清理且 provider 无 `api` 字段时跳过（不误删用户手配）。

## 排除与列表

- **`excludes` 是「零操作排除」**：命中者在 provider 循环入口整条跳过，已写入值原地保留（插件无字段来源记录，清除必误删）。瓦片释义与 README 写明「仅对保存之后的行为生效」，正确顺序是先加排除、再建提供方。
- **必须允许填入不存在的 id**，故不做候选约束；UI 用「N 命中」表达，0 命中也常驻普通样式、不画错误色；命中判据取 `llm-pi-ai` user 层 `providers` 键（与 `fix` 遍历同源，零漂移）。
- **不自动清理失效 id**（顺手 prune 会清空用户列表，顺序是录入意图）：去重两层——录入端当场拒写、`selfHealConfig` 兜手改文件（仅 `Set` 收窄变短才产出 op）。`fix` 写回只写 `llm-pi-ai` 段，不碰自有 NS 键。

## 参数来源

- **图片模态只缓存正向信息**（纯文本省略控体积，`pdf`/`video`/`audio` 忽略）；容量哨兵 `99999999` 与 0 视为无数据（写 0 会被宿主 schema 拒绝并连累整批）。
- **id 匹配宁可漏不错配**：精确 → 词干 → 前缀三级，词干/前缀多命中即判无命中；匹配在归一空间进行（目录索引存归一键，条目本体由 `byId` 反查）。定位两级：组内依次 完整 id → 裸名 → 末段唯一；全局仅跨提供方唯一命中才认（同名常多家重复）。末段唯一仅在 provider 严格匹配时启用（定域后无歧义；兜底遍历与官方提示两处不启用）。
- **「尽量匹配」（`userExperience.looseMatch`，默认关）**：无命中/歧义不放弃——收集全部兜底命中；仍无命中才用归一裸名全局 includes 扩展候选（只在无更优候选时用）。合成：容量取有值候选的 60 分位（官方 ×5 不展开进分位——单条官方条目即可顶高 N，实际踩过；不设支持率门槛）；推理档位逐档取 60% 权重支持、image 取 60% 候选为 true（官方 = HINTS 值集合 ×5，其余 ×1；off 键保留目录原拼写）。全字段落默认仍 undefined（宁可漏不错配）。组内新增键、不递增版本。
- **前缀候选表 `HINTS` 是依序数组**：同一模型常同时挂多个官方条目（镜像），只提示一个会漏；全部候选与兜底遍历互斥。裸 `o` 不作前缀（会吞 `ollama-` 等一般词），`o1`/`o3`/`o4` 逐项列。
- **缓存诚实保留目录的 off/none 拼写，不归一不合成**；`toReasoningEfforts` 写 `off` 键用目录原值而非 `null`（`null` 宿主语义是「省略参数」，默认思考的网关等于没关）。目录未列关闭档的模型档位表不含 off，宿主按「不能关闭思考」处理。
- **档位只代表「能通」，不代表「能关」**：探测与验证只判受理（收到 `block-start`）；探测不为未声明 off 的模型补 off 档，已声明的探测其原值、不做拼写切换（一个 off 键只带一个拼写）。

## 推理级别记忆

- **`efforts` 是运行时记忆而非用户配置**：嵌套对象、宽松解析（坏结构回落 `{}` 不判整段非法）、`isDirty` 不比较它；卡片保存整段快照时 `efforts` 取写入当刻实时值（草稿副本会覆盖开卡后的新记忆）。
- **Node 半只管持久化与解析，不自动设级别**：自动恢复与自动 high 走前端 `directory.select`，自动设置不写记忆（`pendingAutoSet` 守卫跳过反向触发的投影变化）。
- **失效清理归 Node 半、按宿主全量模型列表剪枝，`fix` 不参与记忆生命周期**：存取与恢复都要会话投影且设级别只能走前端，故留浏览器半；清理两样都不需要，「模型还在不在」Node 半直接查得到。清理面覆盖全部活路由模型，塞进 `fix`（只认 llm-pi-ai）不自洽。缺席即删除、段删空折叠（瓦片文案承诺「删除即清除」，残留才是用户可见的 bug）；**读不到 ≠ 不存在**（某 provider 读失败整段保留，退化读整轮不剪）。档位是否仍被公告不参与剪枝（档位表会漂移，恢复侧已守过一次）；不用 `buildModelCatalog`（逐模型 `resolveModelInfo` 可能打网络，且默认参数求值会执行未 inject 的 `ctx.agentDefaultModel`）。
- **`rememberEfforts` 关闭只停「保存新的」，恢复照常**；清空由卡片在开关转关时立即确认（经 settings scope 直写，「有记忆」判据取实时值，清空失败显式报错）。
- **`defaultHigh` 三条护栏**：记忆优先（有记忆即跳过）、不覆盖既有级别、不干预同模型改级别（含手动选「provider default」）。
- **浏览器半记忆写入三条护栏**（`rememberEffort`）：整段 `set` 的基底必须是可信快照——ConfigForm 未 ready 时 `efforts` 回落 `{}`，以其为基底等于清空全部记忆，故放弃本次保存（记忆可丢，误清不可接受）；ready 后带 `expectedRevision` 围栏，`SETTINGS_CONFLICT` 重读重算限次重试（按旧段回放会盖掉他方刚写的条目）；非冲突错误静默放过（记忆是可丢数据）。

## 子智能体

- **在宿主 `agent/request` 瀑布里改写**：子智能体没有独立档位设置面（宿主 `sessions.subagentAddress` 主动屏蔽了被寻址子会话的 model-select 入口），委派落地的调用配置流经该瀑布是唯一可读可写处。种子配置被 `deepFreeze`，只能返回新对象；插件根 ctx 未打 scope 标签 ⇒ 单个 `{ prepend: true }` 监听覆盖全部 Agent。
- **「跟随」以宿主「允许 Agent 为子智能体选择模型」设置关着为前提**：宿主开着时路由由模型在授权范围内自挑，覆盖即推翻合法选择；关着（或读不到）时子智能体只有继承父路由一条路。浏览器半同读这段 settings 判定「跟随」状态灯（段缺席视为未开启）。
- **`followParent` 落在 `userExperience` 组、不递增版本**：会话侧体验开关，与模型配置写入无关、不读 `excludes`；组内新增键向后兼容。
- **跟随父「下一次请求该用的路由」**：先读父会话待生效选择（投影 `pending`），读不到回落请求头 `config`，再无回落 `options`——pending 优先让子与主同一条规则（UI 切换后不必等父发一次请求）。三项照父的来；`adapterDefaults?.reasoningEffort === true` 是适配器默认值，跟随时删键（否则「没选」变「选了默认」）；待生效选择无档位即父「选了模型未选档位」，同样删键。`maxTokens` 不照抄：父不大于子（缺项视作不限）取父的；父更大只抬升差值八成、向下取整——直接顶满新值部分端点会拒，「刚切模型就 400」比发挥受限更糟。每请求现算、不缓存（子智能体是建子快照，新委派必然晚于父的每次切换）。
- **不预检档位可用性、不自动降级**：宿主派发前本地校验（`resolveCallWithInfo`），未声明档位不出网；跟随时写入的是父刚生效的档位（同一条校验刚验过），插件侧再查一遍反而与宿主判定漂移。另有「探测档位」可逐档试出实际支持档位，定位是写配置、不是替用户决定。

## 写回端点

- **启动迁移写回带 `SETTINGS_CONFLICT` 限次重试且必须重读重算**：启动期自有段不止迁移在写（浏览器半记忆监听直写、适配器事件触发剪枝）；冲突后按旧段回放整段 set 会盖掉他方刚写入的内容，重算则让他方已补齐的字段自然收敛为零。
- **`queueTask` 对 HMR 注入做有界等待而非组件级依赖或缓冲队列**：注入落地（含缺席降级）前封顶 2s、只等一次，超时裸 `task()`。不加 hmr 进组件级 `inject`——PENDING 无超时，hmr 缺席会永久挂死整插件；不用缓冲队列——hmr 永不到达时任务永挂。
- **重置不写配置段、不改开关**（关开关等于替用户改配置）；竞态靠 Node 半模块级计数守卫（置位先于 mutate 同步完成，持有可嵌套、解除只折抵一次）。
- **恢复是「改错了想后悔」的整批回退，不受 `excludes` 约束**（逐模型跳过排除项会造半恢复中间态）：共有 provider 的共有 model 回退 + 被删 model 复活（备份原序追加末尾）；被整删的 provider 不复活（连同 key 没了，复活看得见用不了）；启动后新增原样保留。备份是 model 整对象内存快照，只在 `apply` 最顶部捕获一次（晚于写回捕到的是填充过的内容，比没有更危险）；备份缺失或当前无 `providers` 段显式抛错（回 0 会与「确无可恢复」混淆）。
- **三个写回端点各带 10s 等待上限，上限只中止等待、不声称写回未发生**：客户端中断传不到 handler，Node 半照跑完、写回可能已落地，故超时文案说「未收到结果（写回可能已生效）」；不与卡片卸载联动（中止换不来回滚）。

## 验证

- **只读诊断、只由用户主动发起、结果即用即弃**：不写 settings、不占事件流守卫、不进配置键。
- **只判「适配器是否开始产出内容块」**：提示词 `Just say OK`，首个 `block-start` 即成功立即中断（省额度）；`usage` 不算受理（额度耗尽的 key 也会先来 `usage`，据此会把坏 key 判成可用）；每个模型只发一次不带 `reasoningEffort` 的请求（不带参数才是用户实际走的路径，逐档是「探测档位」的职责）。
- **超时两级硬闸、到点必返回、不依赖适配器配合**：30s 软超时发中止信号等宿主归一 `aborted`，3s 宽限期满硬兜底直接返回 `'timeout'`。赛跑对象是每一次 `next()`：到点不再调用、停在未决那次上，随后对迭代器请求关闭（abort + detached `return`，不 await）。硬兜底必须存在：`Promise.all` 只认 `probeOnce` settle，适配器忽略 signal 时读流永不结束 ⇒ 整轮不收尾 ⇒ 事件流守卫永久为真。兜底结论外部中止优先归 `'aborted'`（用户按停止不是超时，记成超时会错误短掉整组）。
- **失败分类只认 `code`，全程不比对文案、不看 `status`**：宿主把上游状态码压成文案（`classifyPiAiError` 正则认 code），「status 缺失即不可达」实测踩过错（一次 400 未识别掉兜底被误判断线）。分类：档位不支持 / 额度（`QUOTA`、`ACCOUNT_QUOTA`，只压该模型不压整组）/ 凭据无效（`INVALID_CREDENTIAL`、`MISSING_CREDENTIAL`，不认 `AUTH`）/ 端点不可达（只认传输层 `TRANSPORT`、`STREAM_CLOSED`）/ 限流与超时（瞬态：只否定这一次，不短后续档位——实测 429 隔一会儿就通）/ 其它（`EMPTY_RESPONSE` 等）。
- **短路只一条判据：能断定后续必然失败才短**，两级。provider 级（同 url 同 key）：端点不可达 / 凭据无效 / 本组首个请求超时（成因在请求之外；理由记 `timeout` 不记 `unreachable`——超时不是传输层证据）。模型级只对逐档请求（验证每模型一条请求，无档位尾可短，归「探测档位」）。
- **汇报明细与统计并行**：明细 `results` 只含实际发出的请求（被短路的没有结论；没跑的由 `planned − probed` 给出）；`tested` 取自计划（勾几个算几个）；`failure` 保留宿主原始 `code`/`message`（分类不依赖 message）。收尾行只报模型口径（请求不带档位）。
- **每 provider 单并发、跨 provider ≤5、不退避**：串行链规避 429。总量封顶 200 模型，超出整体拒绝而非静默截断（截断会让用户以为全查过）。列表默认不预选（预选全部 = 误点即扣费成默认路径）；分组头「全选」键的文案判据与点击方向共用 `groupAllPicked` 纯函数（两处各写 `every` 不同步会「显示取消、点击全选」）。
- **弹层自确认**：候选框内已有 warn 额度提示与 warn 语义验证键，不再叠二次确认；卡片 footer 触发键同样取 warn 语义（警示前移到入口）。
- **在途弹层原地转圈、跑完不关窗**，结论追加记录区末行、不渗透卡片状态行；在途确认键变「停止」（弹层有出口，键不变只能干等）；「停止」按下即追加「已停止，本轮不再继续…」一行（它是唯一不关窗的中止方式，遮罩/Esc/×/取消那几种记录随窗丢）。
- **记录区单列选项卡与模型列表并列**：记录是「正在发生」、列表是「挑哪些」，同屏互相挤。两面板常驻挂载只切 `hidden`（`TerminalBlock` 滚动位置卸载即丢；`total === 0` 给空态）；每次开窗回「模型列表」；发跑后等记录区渲染再切页（`useEffect` 听 `running && total > 0`，`opened` 帧来自异步 SSE，同步跳转拿不到数据）。
- **退出键统一「取消」且在途不禁用**（Modal 任何时刻都能关，禁掉出口只能点遮罩且丢记录）；`close` 只留 × 的 aria-label。
- **进度走 SSE**（`connection.fetch` exact 路由）：验证可能数分钟，事件白名单与 stream Remote 编译期硬编码都不可行；`text/event-stream` 绕 gzip 缓冲，`request.signal` 在客户端断开时 abort；用 `fetch + getReader()` 而非 `EventSource`（自动重连 = 重跑整轮）。
- **关窗 / 断连 / 停止一律中止**：宿主把中止归一 `aborted`，Node 半单列 `'aborted'` 不发帧、不入明细、不短后续档位（防上游自发中止被记成「不可用」再甩锅短路）；消费方据「流结束无终帧」判中止。
- **wire 只发结构化帧，文案全在浏览器半**：locale 只存在于浏览器半，文案归 Node 半等于绑定 Node 产物。帧是判别联合（`opened`/`probed`/`done`/`failed`），行模板由浏览器半拼；`done`/`total` 与统计口径一致（被短路未发出的计入，`done ≤ total`）；`decodeProgressFrame` 逐字段校验（`done.summary` 直接驱动卡片数字）。`failed` 终帧带 Node 半中文原因（裸报「已停止」会吞掉原因）；Node 半不为 `failed` 另打日志（已随帧展示，避免测试输出刷堆栈）。

## 探测档位

- **验证、探测档位、能力探测共用聚合器逻辑渠道规则**：模型 ID 第一个 `/` 前的字符串作为渠道名（如 `wb/cn:deepseek-v4.1-flash` → `wb`）；无前缀的模型回退到实际 provider。只用于分组、短路与汇总，不改发给宿主或 wire 请求的完整模型 ID。凭据错误 / 端点不可达只短路当前逻辑渠道，不误伤同一聚合器的其他渠道；首请求超时也按当前逻辑渠道判定。未派发条目的进度帧通过 `skippedReason` 与逻辑渠道名标明真实原因。
- **探测档位的并发上限**：同一实际 provider 最多 3 条模型链同时在途，该上限由同一网关下所有逻辑渠道共享；同一模型的各个推理等级严格串行。模型级额度耗尽 / 限流只跳过当前模型剩余等级。
- **并发下的首个请求超时按逻辑渠道判定**：只有某个渠道第一个发出的请求超时，且该渠道没有其它请求先完成时，才短路该渠道；另一个渠道的成功响应不再掩盖它的首请求超时。

- **先预声明候选档位再探测**：宿主按配置声明的档位本地校验，未声明不出网——不动配置无从探测。预声明同一轮被收敛写回收回，增删统计以预声明前档位表为基线（临时档位不计增删）。
- **收敛写回在流内完成、终帧最后发**：收敛依赖预声明前档位表（只在 Node 半本轮内），拆端点就得让浏览器回传可能已过期（探测期间用户改过配置）的旧表。
- **模型级短路 = 额度耗尽 + 本功能自有的限流**（验证那套限流瞬态不短，这里短）：限流不分档位，同窗口同 key 剩余档位大概率同样 429，而被短模型走「没跑满即还原」、档位表原样不动，无错杀好档风险；上游 5xx / 其它拒绝 / 超时不短（多为一次性故障）。
- **不加「不带档位的基线探测」**：档位请求的对照更紧——更低档跑通 ⇒ 端点/凭据/额度/网络/模型名全无碍，唯一变量是这一档，代价为零；基线只多换「off 自己可判不支持」，而 off 被拒不判不影响补全，却让每个模型多烧一次请求。
- **判「这一档不支持」第二条件：同模型已有更低档跑通**；首档即 `INVALID_REQUEST` 只记「其它」（更可能是模型本身的问题，判不支持会误伤好档位）。
- **两种收敛口径由「剔除不支持」选**：关 = `可用 ∪ 原有`（只增不减），开 = `可用 ∪ (原有 − 明确判不支持)`；两条只认明确状态（限流/超时/额度/不可达都是「没验成」，拿它动用户配置是误伤）。档位表算空即整键删（与填充同一空壳判据）。
- **「剔除不支持」只对已声明档位的模型有意义**（未填充模型判不支持的档不会写入）；「自动写入」关闭或在途时该开关禁用（避免亮着却不生效）。
- **没跑满即还原、中止整轮还原**：半截结论不足以动用户配置，「探到多少补多少」不可预期。
- **探测范围发跑时冻结**：两次写回只覆盖冻结清单（预声明写了谁、收敛还谁）。
- **开跑前把目标档位表原值 base64 存自有段顶层 `probeBackup`（不进版本快照、不动 `CONFIG_VERSION`），启动末尾见键即回退并补一轮 `fix`，回退成功才清备份**：崩在中途收敛没机会跑，预声明留在配置里，落盘备份是唯一退路；只备探测目标那一个字段（整段备份会连带撤销范围外的正当编辑）；只编码不压缩，存不下整轮中止——没有退路就不动用户配置。
- **清备份放收敛落盘之后**：唯一残留窗口是「收敛已落盘、备份未清」被杀（下次启动多回退一轮，再探一遍即可），反过来先清则崩在收敛前无人回收预声明。
- **中止恢复走内存基线**（预声明前的 `preexisting` 表）：粒度更细、零落盘；改走备份会把没碰过的模型一并按备份覆盖。中止后收敛写回失败时清备份不执行，备份留下、下次启动幂等回退。
- **事件流守卫持有整轮**：放开后用户改配置会触发 `fix` 把预声明按目录改回去，剩余探测全被本地拒绝、结论全错；代价（期间其它写回被拒、自动填充暂停）小于一轮主动发起的探测带着未收敛写回的风险。
- **收尾不自动关窗**：结论在记录区末行，两种收尾形态（写入 / 只汇报）都留在窗内，由用户看完关。
- **配额封顶 200 模型（≤1400 请求），超出整体拒绝**（沿用「不静默截断」纪律，与验证同一 `ProbeLimits`）。
- **「自动写入」默认开且每次开窗重置为开；Node 半缺键取开**：关掉的旧前端不带该键会让整轮白跑（探完全还原）。关闭时收敛照算不落盘，终帧 `fill` 携带「可补全」假设统计。

## 能力探测

「能力探测」= 图片输入 + 工具调用两条 wire 级探测；判定规则来自 03-probe-audit.md §1.1/§1.2 的裁决（工具调用看 `tool_calls`/`finish_reason` 而非 2xx；图片 1x1 PNG 三态 + data URI 回退）。

- **不走 `llm.stream`、新开裸 HTTP wire 层（`src/probe-wire.ts` + `src/probe-caps.ts`）**：判定规则要求 wire 级控制，`llm.stream` 三样都给不了——① `GenerateOptions` 无 `tool_choice`（docs/host-api.md 字段表），不强制则「模型回文本」无法区分「不支持」与「不想调」；② `ImageBlock` 的字节与编码归 attachment 服务与适配器，「data URI 优先、仅拒内联编码才回退」要求我方控制出线编码并按拒绝原因决定重试；③ pi-ai 路径的失败 `status` 恒缺、响应体被归一成 `LlmFailure.code`，判定要看的原始 status 与 `choices[0]` 无从取。执行骨架仍复用 `runProbeGroups`（分组、五路 worker、帧协议），差异只在 `GroupRunner` 回调（它不碰 `llm`）。
- **方言范围 v1 只认 `api === 'openai-completions'`**（`POST {baseURL}/chat/completions`）：其它方言与**未声明** `api` 都不发请求、记 `unknown` + 原因 `dialect-scope`——未声明时宿主会复用已装 provider 自己的方言，形状无从猜，宁可不测也不拿错误形状的 400 误判「不支持」。方言扩展是显式扩展点，不在本轮。`baseURL` 直接拼 `/chat/completions`（带不带 `/v1` 由用户配置负责，不猜不改写）。
- **凭据解析：`apiKey`（明文）优先，`apiKeyEnv`（引用名）经 `ctx.credentials.resolve` 分层解析（进程环境 → provider 存储 → .env），回退进程环境**（与 llm-pi-ai 适配器 `resolveApiKey` 同口径）；解析不到记 `no-credential` 不发请求。已知取舍：`resolve` 拿不到的凭据形态（如 OAuth 会话）无从出线，如实报「未得出结论」。**密钥只进 `Authorization: Bearer` 头，不进日志、不进帧、不进任何返回值**；鉴权头 v1 仅 Bearer（Azure `api-key` 等留扩展点）。
- **图片判定三态 + 回退链**：200 = supported（`max_tokens=1` 本就没内容可看，不要求复述）；4xx 含 `image`/`vision` = unsupported；5xx/网络/超时 = unknown。**内联拒绝特征（`data:`/`base64`/`inline`/`uri`/`url format`）优先于「不支持图片」判定**：拒收 data URI ≠ 不支持图片，先回退仓库资产 raw URL（`assets/probe-1x1.png`，与内嵌 data URI 常量同字节、随 fork 提交、不依赖第三方图床）重试一次再判；回退后不再重试，按同一矩阵落终态。关键词判定是启发式，误判代价不对称——判 unsupported 会删用户配置，故宁可多一次回退请求。
- **工具判定：2xx 不单独作数**——必须看到 `choices[0].message.tool_calls` 非空或 `finish_reason === 'tool_calls'` 才 supported（对 model-catalog 探针「只看 2xx」的明确修正）；2xx 无 tool_calls（网关忽略 tools）= unsupported；4xx 含 `tool`/`function` = unsupported；其余 4xx / 5xx / 网络 / 超时 = unknown。响应体容错解析（字段缺失、坏 JSON 一律按「无 tool_calls」）。
- **三态一律附 `reason`**（原始 status + ≤200 字错误体摘要；非 HTTP 收场给稳定标记 `timeout`/`network`/`dialect-scope`/`no-credential`/`no-endpoint`；raw URL 回退后通过留 `fallback=raw-url` 痕）。响应体有界读取（64K 字符截断），超长错误页不整页进内存。
- **短路沿用 provider 级语义**：401/403（凭据无效）、端点不通（网络失败）、本组首个请求超时断到组尾；429 只算本次没结论不短路；方言/凭据/端点短路是**不发请求**的逐条 unknown（用户看得出为什么没测），不进 skipped。外部中止（停止/关窗/断连）不入账、不发进度帧、不发终帧；若上游单次请求主动返回 `ABORTED` 且外部信号未取消，则不入结果明细、不中断整轮，但发一条 `outcome=aborted` 的进度帧结算该计划项，确保最终进度 `done=total`。
- **写回只动 `input` 图片模态一个字段**：supported 且「自动写入」开 → 写 `['text','image']`（`MODALITIES` 只有 text/image 两值，写全集不丢任何东西）；unsupported 且「剔除不支持」开 → 删 `input` 键；unknown 一律不动；**工具调用无官方字段，只展示不写**（「顺手补个字段」= 捏造配置）。绝不写 `reasoningEfforts: {}` 空壳（过不了 provider 校验、连累整批写入）——重建模型条目照旧过 `stripEmptyFields`。无预声明故无两步写回、不需要 probeBackup；写回走 `guardedWritebackApi`（冲突重读重算限次）。
- **中止整轮不写回**（口径与探测档位「中止整轮还原」同源）：半截结论不足以动用户配置；「自动写入」关闭只算不写，终帧 `fill` 是可写入的假设统计（两义同 `ProbeFillResult`）。
- **计费控制**：每「模型 × 能力」一条最小请求（`max_tokens=1`、单条消息、1x1 图），data URI 回退是同条目内的唯一重试；弹层 quota 文案明说「真实计费请求 + 最小请求形态」；全程可取消。配额 `CAPS_LIMITS`：模型 ≤200、计划 ≤400 条（每能力 ≤200），超出整体拒绝。
- **开关语义与探测档位对齐**：「自动写入」缺省开、每次开窗重置为开；「剔除不支持」缺省关（只增不减）且只在自动写入开时可切。文案沿用 `probeAutoWrite`/`probeDropUnsupported` 两键；「剔除不支持」的释义在能力探测里只讲图片模态（工具调用没有可写的字段），故另给 `capDropUnsupportedTip` 而非复用档位释义。
- **记录行一「模型 × 能力」一行**（`{provider}: {model} · {capability}：{result}`），三态文案后附原因括注；wire 只发结构化帧（`probed` 帧多带可选 `cap` 字段、`done` 汇总多带 `caps` 计数），文案全在浏览器半（口径同「验证」条目）。

## 宿主与卡片

- **RPC channel 在已注入 webServer 的子 fiber 上自注册**，不用宿主 `connection.rpc.handle`（它在 connection 服务 ctx 上求值 `owner.webServer`，而 connection 不再注入 webServer，必抛）；信任围栏复用宿主 `requestRejection`。
- **卡片按钮取「保存」不取「应用」**：写 settings 即前端职责终点，填了几条前端无感知。瓦片默认收起、同时只展开一个（官方手风琴语义）；「取消」键仅未保存时渲染。
- **输入框弹层用 Modal headless 形态**：卡片即唯一可见层，不套宿主 chrome（与卡片 header 重复两层标题）；面板高度内容撑开、640px 封顶；该席禁折叠（折叠让内容与指针脱钩）。
- **浏览器半编排挂 `configForms` 子 fiber 不挂父 ctx**：cordis 的注册清理只归调用方自身 fiber，挂父 ctx 时子 fiber 重建不清理旧注册（二次 `locale.register` 抛 `already has locale`、slot 重复注册）；挂子 fiber 则重建前先级联撤销。
- **`behavior` 组管 UI 装卸不是插件行为**：四个开关只决定部件在不在，功能本体照常运行。
- **开关必须落到「注册 / 撤销注册」**：宿主 tab 头按注册账本画，组件返回 `null` 只空内容、tab 头照旧（点进去空白选项卡）。
- **注册动作必须写在 `inject` 回调里**：向未声明 slot 注册即抛，该抛错发生在 fiber 启动期、连累同 fiber 后续全部注册（实测五席全没注册，症状「开关全开但一个界面都没有」）；`inject` 回调返回的清理函数被宿主挂进该次声明的 effect，生命周期归宿主管。
- **工具栏两枚 chip 各占一个席位条目**：宿主 list 席位按 `id` 记账，两者管的事不相关（打开设置 / 跟随状态），各由 `behavior` 一个开关支配（`order` 5/6 定先后）。
- **chip 字色三档语义（弱化 / 生效 / 失败）**：模型优化恒 `label-secondary`；跟随未生效降 `label-caption`（同宿主当前级别色——「有个值摆着、此刻不参与决策」，与模型名同权会把关闭误读成正常）；生效 success 绿、失败 warn 琥珀，另加 6px 状态点（非生效不画，关闭与弱化还有形状差）。
- **「插件管理」唯一不可关闭、故不落配置**：`lockedRow` 恒开禁用展示行，不绑键、不进脏检测；给了开关关掉后无处可改回。
- **`behavior` 缺省方向与其它组相反**：缺字段落**可见**（loading 落不可见会让首屏凭空少一块且用户分不清是加载中还是被关了）；组内取值仍严格布尔，显式 `false` 才卸载。
- **瓦片总控按 `every` 显示**：全开显开、部分显关、点击整组补全（`any` 点击会抹掉用户已勾的行）；总开关本身无存储，只是批量操作。
- **卡片底部分三段**：动作键行（靠左可换行、分隔线之上）/ 分隔线 + 取消·保存（靠右）/ 分隔线 + 联系行；动作键行不设分割线（承接瓦片，分隔线只分「正文」与「页脚」）。
- **不引入 `failed` 态、不做「恢复默认」**：三组布尔恒合法、原子写，失败时 `dirty` 已传达；官方 reset 依赖字段级 user/base 分层，本插件是整体显式快照。
- **对外报告状态的文案一律句号收尾**（状态行是卡片上唯一报「刚才那次操作结果」的位置，两种语气读起来像两种语义）；例外两类：加载省略号、诊断记录区逐条结果（数据条目非句子）。
- **「隐藏官方API」拦在模型目录生成处、不改官方 provider 配置**：宿主 UI 目录唯一生成链路是 `buildModelCatalog` 逐 provider `listModels` 后滤空组，遮 `listModels` 即生效；写官方 `models` 配置实测不生效（官方适配器对 `models` 有 `.default(DEFAULT_MODELS)` 兜底，清空配置不等于目录里没模型，且写配置要备份回填、崩溃留半截状态）。
- **名单只放 `deepseek-official`**：`deepseek-account` 段无 `apiKeyEnv` 键，判定会回退到 `DEEPSEEK_API_KEY` 误隐藏可用账号组，且该 provider 自 `0.1.7-rc.2` 起自带登录门。功能本身保留：宿主 `0.2.1-alpha.2` 起才原生做这件事，老宿主上本插件是唯一手段。
- **不挂任何事件、判定逐次现算**：遮蔽处是全部消费者共用的（目录生成、可用性校验、记忆剪枝都走 `listModels`），缓存会让「刚翻转开关 / 刚配密钥」与旧结论不一致；UI 目录刷新本就由宿主服务负责，插件再挂一遍只是重复评估。
- **卸载只清状态位，不 `delete` 属性、不写回原函数**：遮蔽是链式的（后装插件的 `original` 正是本层），动属性会落别人层上或抹掉别人遮蔽；状态位先判也解决 fiber 失活后读 `ctx.llm` 抛错。
- **「本地化推理级别」换在 Node 半 `resolveModelInfo` 层**：档位显示名只在它返回里出现（目录、UI 菜单、subagent 工具全取它），遮这一处全链覆盖；浏览器半三条路都比它面大（zustand+immer freeze、目录实例在私有字段、`ctx.remote.session` 与服务键不是同一对象）。已知取舍：开关开时 AI（list-models 工具文本）看到的档位名也是中文。
- **`defaultEffort` 不翻译**：它是档位 id，宿主校验它落在 `efforts[].id` 集合内（不合法即抛）；UI 显示默认档位走「id → name」，那个 name 已被换掉。
- **语言判定三路**：settings `locale.preference`（显式选择落盘）→ 浏览器启动时 RPC 上报（进程内易失）→ 回退 `en`（不换名）。
- **词表键取宿主显示名形式（id 首字母大写），键集挂共享层 `EFFORT_LEVELS`**：查表键与界面所见逐字对上；非全小写档位（如 `HIGH`）宿主显示原样、不落七键、透传交作者命名；`Default` 是宿主自合成伪菜单项，与七档同表维护（代价：表类型退化为 `Record<string,string>`，键集由测试兜住）。
- **「显示原档位名」：中文名后追加 ` · 原名`（分隔符共享常量）**：单看「最大」无从对照。Default 伪菜单项走浏览器半词典 patch（`locale-patch.ts`），与 Node 半共用同一分隔符常量。
- **Tooltip 方向一律 `side="top"`**：卡片上方有 header、弹层居中，上方总有空间；展开体帮助图标贴行尾，右侧空间窄。

## 档位自调

- **注入两枚工具 + 一段提示词**：档位该多高天然长在会话过程里，AI 信息最全；开关开装关卸（随自有段变更热更），插件零状态（档位全在宿主），HMR 无损。
- **设置走 `sessionController.selectModel`**：与 UI 手选同一链路（落 `model/selection` 事件、宿主照常校验）；不走 `agent/request`（子智能体跟随的领地、只影响单请求），不直写 `llm-pi-ai`（绕开宿主校验、把会话级选择降格成全局配置）。
- **查询走 `llm.resolveModelInfo`（全量提供方）**：可用档位的权威来源是适配器元数据（宿主校验用的就是它）；与设置共用同一条路由回落链（投影 `pending` → `lastUsed` → 请求头 → options，与 `src/subagent.ts` 同规则）。
- **档位值一律用 `efforts[].id` 实际值、不设 `'default'` 哨兵**：档位 id 由适配器自定（`off` 未必存在、语义也未必是默认）；AI 实际只有升/降两个操作，「默认档位」对它无用。
- **唯一失败形态「模型不支持该档位」，`RemoteError` 原样透传**（宿主已归一失败面，再改写丢信息）；入参失败回业务失败值（`ok:false` + `error`），AI 读得到原因才能自行纠正。
- **「先查后设」软指引不硬校验**：路由可能在两调用间被 UI 切走，硬校验挡不住真错、只挡合法用法；提示词只指明失败后重查一次、仍失败保持当前档位。
- **四个宿主服务经 `ctx.inject` 子 fiber 门控**（全就绪才执行、缺席仅该 fiber PENDING 静默）：插件级 `inject` 会让缺服务的宿主永久挂死整插件；工具/提示词 disposer 挂宿主服务自身 ctx，子 fiber 卸载须 `ctx.effect` 手动调；注册中途抛错回滚已注册部分。
- **`selfTune` 与 `followParent` 同批落 `userExperience`、不递增版本**：同为会话侧开关；解析端缺键落默认 false，台阶产物补同一默认（不变量：DEFAULT_STORED 与升级链空输入一致）。
